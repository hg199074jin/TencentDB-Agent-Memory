# Codex、Claude Code、ZCode 共享记忆 MVP 设计

## 1. 目标

在不改变三个 Agent 现有模型供应商和调用线路的前提下，让 Codex、Claude Code、ZCode 读写同一个 TencentDB Agent Memory 记忆空间。

首版只验证一个核心结果：

> 在一个 Agent 中说过的内容和个人偏好，能够在另一个 Agent 的新会话中被自动召回。

## 2. 当前基础

- 仓库位于 `D:\TencentDB-Agent-Memory`。
- 当前部署已经包含 MemoryCore 和 Memory Hub。
- MemoryCore 通过本机 HTTP Gateway 提供 v3 记忆接口。
- 仓库官方适配模式已经明确：回答前召回，回答后捕获，L0 到 L3 的处理交给 MemoryCore。
- Claude Code 当前直连 MiniMax；Codex 和 ZCode 继续使用各自现有模型线路。

## 3. MVP 范围

### 包含

- Codex、Claude Code、ZCode 三端自动召回记忆。
- 三端自动写入本轮用户消息和最终回答。
- L0 原始对话立即共享。
- L1 原子记忆和 L3 用户画像长期共享。
- 写入失败时在 D 盘暂存，后续自动重试。
- MemoryCore 不可用时，三个 Agent 继续正常工作。
- Memory Hub 用于查看记忆结果。

### 不包含

- 不经过 MemoryProxy 转发模型请求。
- 不修改 Memory Hub 前端。
- 不做自然语言编辑、删除记忆功能。
- 不接入 Skill、Wiki、CodeGraph。
- 不导入历史聊天记录。
- 不自动识别 Git 项目或建立项目级 Task。
- 不增加新的常驻后台服务。

## 4. 总体架构

```text
                     模型调用线路（保持原样）

Codex ───────────────────────────────► OpenAI
Claude Code ─────────────────────────► MiniMax
ZCode ───────────────────────────────► 当前供应商

                     记忆调用线路（新增）

Codex Hook ─────┐
Claude Hook ────┼──► 共享记忆适配脚本 ──► MemoryCore :8420 ──► L0/L1/L2/L3
ZCode Hook ─────┘                                      │
                                                       └──► Memory Hub 查看
```

模型调用和记忆调用是两条相互独立的线路。记忆故障不得影响模型回答。

## 5. 固定身份映射

MVP 复用原仓库已有的身份隔离机制，不增加自动项目映射。

三个客户端共用一组固定身份：

| 字段 | MVP 规则 |
|---|---|
| `serviceId` | 共用当前 MemoryCore 实例 |
| `teamId` | 固定为同一个 Team |
| `agentId` | 固定为同一个逻辑“个人助手” Agent |
| `userId` | 固定为同一个用户 |
| `taskId` | 固定为同一个通用 Task |
| `sessionId` | 每个会话独立，并带客户端来源前缀 |

会话标识示例：

```text
codex-<原会话ID>
claude-<原会话ID>
zcode-<原会话ID>
```

实际 ID 在实施时优先读取现有 Memory Hub/MemoryCore 元数据；不存在时再创建一次，并保存到统一配置文件中。三个客户端不分别创建身份。

## 6. 回答前召回

每次用户提交提示词时，对同一固定身份执行跨会话召回：

1. 用当前用户问题搜索 L0 原始对话，作为“立即共享”来源。
2. 搜索最多 5 条相关 L1 原子记忆。
3. 读取 L3 用户画像。
4. 合并为有明确边界和来源标签的简短上下文。
5. 通过当前客户端 Hook 支持的上下文字段注入，不修改用户原文。

召回上下文必须标记为历史参考信息，不能覆盖用户当前指令，也不能被当作工具授权。

任一路召回失败时使用其他成功结果；全部失败时返回空上下文并继续回答。

## 7. 回答后捕获

每轮 Agent 完成回答后：

1. 取本轮原始用户输入。
2. 取本轮最终助手回答。
3. 清除系统指令、工具日志、召回注入内容和多媒体 Base64。
4. 使用带客户端前缀的 `sessionId` 调用 v3 `addConversation()` 写入 L0。
5. 后续 L1、L2、L3 提炼继续由 MemoryCore 后台完成。

只写本轮新增内容，不重复提交完整会话历史，避免重复记忆和召回反馈循环。

## 8. 三端适配方式

共享逻辑只实现一次，各客户端只保留很薄的事件转换层：

| 客户端 | 回答前事件 | 回答后事件 | 作用 |
|---|---|---|---|
| Codex | 对应的提示词提交 Hook | 对应的完成/停止 Hook | 转换为统一召回和捕获输入 |
| Claude Code | `UserPromptSubmit` | `Stop` | 保持 MiniMax 直连不变 |
| ZCode | 提示词提交 Hook | `Stop` | 转换为相同统一输入 |

实施前必须读取三个已安装版本实际提供的 Hook 输入样例；适配层只依赖公开字段，不读取或修改客户端内部数据库。

MCP 不是 MVP 自动记忆链路的必需组件。若某一客户端的 Hook 无法提供必要字段，再把 MCP 作为该客户端的兜底，不预先安装重复能力。

## 9. 故障处理

### 召回失败

- 设置短超时。
- 不重试阻塞当前提示词。
- 返回空上下文。
- Hook 正常退出，Agent 继续工作。

### 写入失败

- 把已经完成隐私过滤的本轮内容追加到 D 盘本地待处理 JSONL。
- 下次任一 Hook 触发时，先有限重试最早的少量记录。
- 使用稳定会话 ID 和时间戳，避免重复写入。
- 待处理文件不包含 API Key、Token 或模型供应商凭据。

### 客户端升级导致 Hook 不兼容

- 只停用发生问题的单个客户端适配层。
- 其他 Agent 和 MemoryCore 继续工作。
- Hook 无论成功或失败都不得阻断 Agent 主流程。

## 10. 最小隐私规则

- 默认只记录用户输入和最终助手回答。
- 不记录系统提示、工具调用日志、中间推理、图片 Base64。
- 不把召回注入的旧记忆再次写回。
- 检测到密码、API Key、Token、私钥等敏感内容时，整轮不写入。
- 用户输入包含 `[不记忆]` 或 `/nomemory` 时，整轮不召回、不写入。
- 日志只记录状态、客户端、会话摘要 ID 和错误类型，不记录完整对话与凭据。

## 11. 配置与文件边界

- 所有新增实现、配置模板、测试和运行数据都以 `D:\TencentDB-Agent-Memory` 为根目录。
- Codex、Claude Code、ZCode 的用户配置目录只写入最小 Hook 注册项，命令指向 D 盘脚本。
- 不把 API Key 写入 Git。
- 不修改腾讯官方 MemoryCore、Memory Hub、MemoryProxy 的业务代码，除非端到端测试证明存在必须修复的兼容性缺陷，并单独记录。
- 自定义适配代码与官方部署代码分目录保存，方便后续更新上游仓库。

## 12. 验收标准

MVP 必须同时通过以下测试：

1. 在 Codex 中说一个此前不存在的新偏好，新开 ZCode 会话能够复述。
2. 在 ZCode 中补充一条新信息，新开 Claude Code 会话能够召回。
3. 使用 `[不记忆]` 后，Memory Hub 中不存在该轮内容。
4. 暂停 MemoryCore 后，三个 Agent 仍能正常回答；恢复后，失败写入能够自动补交。
5. Claude Code 仍直连 MiniMax，Codex 和 ZCode 仍使用原有模型供应商；模型请求不经过 MemoryProxy。

## 13. 完成定义

只有在三端真实安装环境完成上述端到端验证，并在 Memory Hub 中确认 L0 写入和跨客户端召回后，MVP 才算完成。

首版完成后再决定是否增加项目级 Task、记忆纠错、Skill、Wiki、CodeGraph 或更完整的升级维护机制，不提前实施。
